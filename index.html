What this demo shows

✎

Prompt-driven edits

Ask in plain English for a new section, a colour change, or a bug fix. The assistant edits the real files in this repository.

⚖

Standards enforced

Repository instructions tell the assistant how we name classes, structure markup, and use design tokens, so generated code matches the existing codebase.

⚡

Automated deployment

A push to the main branch triggers the workflow and publishes the updated site to GitHub Pages without any manual steps.

☵

Zero build tooling

Plain HTML, CSS, and JavaScript. Nothing to install, nothing to compile, and the whole change is easy to read in a pull request diff.

♿

Accessible by default

Semantic landmarks, labelled controls, and visible focus states are part of the standards, not an afterthought.

☀

Theme aware

Light and dark themes are driven entirely by CSS custom properties defined in one place, so a palette change is a one-file edit.

How a change reaches production

Four steps, one of which is a sentence of English.

  1. 1

    Describe the change

    Write the request in the chat panel, for example “add a testimonials section below the stats”.

  2. 2

    Assistant reads the standards

    Repository instructions are loaded automatically and shape the generated markup, styles, and scripts.

  3. 3

    Review the diff

    The change lands as an ordinary commit or pull request that a human approves.

  4. 4

    Pipeline deploys

    The workflow publishes the site to GitHub Pages and the live URL updates on its own.
